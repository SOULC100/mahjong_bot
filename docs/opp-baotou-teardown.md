## 0. 结论摘要

1. **重建可信度满分**：四家逐巡重建 **789/789** 局赢家终局张数正确、0 条 issue；
   `any_draw_win(摸前13)` 与服务端 `round_ended.data.detail` 的「爆头」标签 **162 = 162，逐条 100% 一致**
   （`python data/_ob_recon.py` B 段）⇒ 本报告的爆头判据与服务器同源。
2. **对手爆头的形状 = 「副露多 + 白多」**：147 手里 **81.6% 带副露**（≥2 摊 51.7%），
   **53.7% 摸前有 ≥2 张白**，`std`（(4−m) 面子 + 单白）137 手 / `seven`（七客）10 手。
   极端例：`a_5b83c31e82d3 b2 r1 seat0` 已经 3 摊，摸前 13 张只剩 **`7b 8b 白白`** 四张 → 摸任意牌胡。
3. **差距 100% 在「到达」，不在「转化」**：进听次数我 1911 / 对手 6057（人均 1911 : 2019，**一样多**），
   但爆头形 **我 0.94%（18/1911） vs 对手 3.05%（185/6057）= 3.2×**；
   而爆头听牌→胡的转化率 **我 83%（15/18） vs 对手 79%（147/185），完全一样**。
4. **「留白」不是差异点**：双方 **100%** 的持白决策都满足 Δ=(白保将向听−白自由向听) ≥ 1（结构性）；
   弃白（财飘/逃）我 **5/6916 = 0.07%**、对手 **45/21083 = 0.21%**，**同一量级且都趋近 0**；
   对手 147 手爆头里只有 **5/147 = 3.4%** 中途打过白。⇒ 保白行为无从改进。
5. **出牌层没有任何可挖空间**（关键否定结论）：出牌当口能直接做出爆头听牌的机会
   **我 18 次（实际全部打出 18/18 = 100%）**；即使允许付 1 向听，能让 `sb13` 变好的点也只占 **1.1%**。
6. **根因 = 副露太少**：持白时碰的转化率 **我 34.9% vs 对手 68.2%**（机会完全相同 0.9/局/家）；
   同一向听下 P(爆头路线还活着) 随面子数从 **15%(m0) → 38%(m1) → 52%(m2)**；
   我胡牌时面子数 ≥2 只占 **23.3% vs 对手 40.2%**。
7. **现有 genome 键全部无效**：`knock=True` 在 800 个真实决策点 **0 翻盘**（并可**证明**是 no-op）；
   `god_fan_boost` 1.5/2.0/3.0 **0 翻盘**；`baotou_slack=2`（不改 max）**0 翻盘**；
   `baotou_slack=2,max=2` 翻盘 10.4% 但**全部是向听变差 1、sb13 不变**（正好解释历史 −0.455, z=−3.47）。
8. **可挖余量有限但要诚实**：出牌通道 **18 个机会已 100% 抓住（余量 0）**；
   只剩**碰通道**约 **+9 个**直接爆头听牌（乐观口径，另 +45 个「离爆头 ≤1 步」）。
   而机会差是 **190 − 18 = 172** ⇒ 决策层最多补 **5~16%** 的缺口，主力必须放在**鸣牌策略**。

## 1. 对手爆头画像（147 手）

### 1.1 结构分布（`python data/_ob_baotou.py B`）

| 维度 | 分布 |
|---|---|
| 面子数（含副露） | 0: **27** / 1: **42** / 2: **53** / 3: **22** / 4: **3** ⇒ 带副露 **120/147 = 81.6%**，≥2 摊 **78/147 = 53.1%** |
| 摸前（13−3m 张）白数 | 1: **68** / 2: **73** / 3: **6** ⇒ ≥2 张白 **79/147 = 53.7%** |
| 形 | `std`（(4−m) 面子 + 单白）**137** / `seven`（七客 = 6 对 + 单白）**10** |
| 面孔里被当百搭用掉的白 | 0 张 **62** / 1 张 **70** / 2 张 **5**（= 摸前白数 − 1） |
| 番 | 2 番 **132** / 4 番 **14** / 8 番 **1** |

**读法**：爆头的机制是「**面子数越多 → 需要的自然面子越少 → 单白越容易剩下**」。
m=3 时摸前只有 4 张牌，只要 3 张自然牌 + 1 张白能凑 1 个面子即可（例：`7b 8b` + 白 = 678b），
所以**副露本身就是爆头的生产线**。

对照组（同一张表）：**我 15 手爆头里 15/15 都带副露**，而我 71 手零副露的胡牌里 **爆头 0 手**。
对手零副露也做出 **27/126 = 21.4%** 的爆头 —— 这一格是我最刺眼的 0.0%。

### 1.2 典型例子（含逐巡代价）

**例 1（副露型极致）`a_5b83c31e82d3 b2 r1 seat0`，番 2**
- 摸前 13 张：`7b 8b 白 白` **+ 副露 3 摊** ⇒ `[std, 白=2, 面孔白=1]`
- 摸到 `3t`（完全无关的牌）→ 胡。`3t + 白` 当将；`7b8b + 白` = 678b 面子。

**例 2（标准 4 面子 + 单白）`a_5b83c31e82d3 b3 r7 seat3`，番 2，无副露**
- 摸前 13：`5w 6w 7w 3t 4t 5t 6t 6t 6t 4b 5b 6b 白` → 4 个自然面子 + 单白；摸 `1w` 胡。

**例 3（全程保白到底）`a_b5bbbd35ed4f b4 r2 seat3`，番 2**
起手 `2w 6w 7w 8w 6t 6t 2b 4b 6b 7b 南 中 白白`（2 张白），第 14 巡摸到第 3 张白：
```
巡4  s14=0 sb14=1  打 西
巡5  s14=0 sb14=1  打 南
...
巡13 s14=0 sb14=1  打 9b
巡14 6w7w8w 4t 6t6t6t 2b4b6b7b 白白白  s14=-1 sb14=0 [爆头形] 打 4t
巡15 摸 5t → 胡
```
**关键**：他从巡 4 起就是「s=0 但 sb=1」—— **听牌但白还差一步**，此后 10 巡全部按 `sb` 走，
从不因为「已经听牌」而放弃把白留成将。

**例 4（同型对照：我）`a_86091a604d7b b3 r3 seat2`，番 2**
我也拿到 3 张白，但我到巡 9 摸 `8b` 才胡，而且**不是爆头**：
```
巡6  s14=1 sb14=3  摸到第 2 张白
巡8  s14=0 sb14=2  打 3w
巡9  4t4t5t5t 4b5b 8b8b9b 中中 白白白  s14=-1 sb14=2 → 胡（平胡，非爆头）
```
**我的 3 张白全部沉在将位/面子外，牌型是 3 对 + 4 孤张**；对手的 3 白型是「2 白补面子 + 1 白当将」。
⇒ 差别不在「白留不留」，在**白以外那 10 张牌的结构**。

### 2.2 「拒绝用白」的频率 —— **100%，双方都是，无信息量**

Δ = `shanten_baotou`(14 张) − `shanten`(14 张) = 「把 1 张白留作将」相对「白当自由百搭」的代价：

| 群体 | 持白出牌决策 | Δ 分布 | Δ≥1 占比 |

| 对手（爆头手） | 2149 | 1: 1290 / 2: 817 / 3~5: 42 | **100.0%** |

| 我 | 2884 | 1: 1159 / 2: 1553 / 3~5: 172 | **100.0%** |

**这是本次最重要的「不是问题」结论**：`shanten_baotou ≥ shanten` 恒成立（留 1 张白做将
不可能让手牌更快），所以「用不用白」在**任何一个决策点**上都不是一个可选项 ——
双方 100% 都在**已经付了 Δ 代价**的前提下打牌。**「我拒绝用白不够」这条假设可以划掉。**

### 3.4 对比「引擎在真实决策点上换键会怎样」（`data/_ob_probe.py`）

把 800 个**真实发生过**的出牌局面喂回 `discard_decision`（线上口径 + 冠军 genome）：

| 臂 | n | 翻盘 | 翻盘% | 其中 s 变好 | sb 变好 | sb 变差 |
|---|---:|---:|---:|---:|---:|---:|
| `knock=True` | 800 | **0** | **0.0%** | 0 | 0 | 0 |
| `baotou_slack=2`（max 仍 1） | 800 | **0** | **0.0%** | 0 | 0 | 0 |
| `baotou_slack=2, max_shanten=2` | 800 | 83 | 10.4% | **0** | **0** | 0 |
| `baotou_slack=3, max_shanten=3` | 800 | 119 | 14.9% | 0 | 0 | 0 |
| `god_fan_boost=1.5 / 2.0 / 3.0` | 800 | **0** | **0.0%** | 0 | 0 | 0 |
| `fan_est="real"` | 800 | 25 | 3.1% | 0 | 0 | **4** |

**两条死开关（可证明的 no-op，建议直接从番型扫描里删掉）**：

1. **`knock=True` 恒等于关**。`discard_decision` 里 `s_map[d] = min(s_map[d], knock_shanten(c))`；
   而 `knock_shanten = min(shanten_baotou, seven_knock)`，且
   `shanten_baotou ≥ shanten`（留白不可能更快）、`_seven_knock_dist ≥ _shanten_seven_pairs`（少用一张白不可能更快），
   已有 `shanten = min(standard, seven)` ⇒ **`knock_shanten ≥ shanten` 恒成立，`min()` 永不生效**。
   手牌级验证（`_ob_baotou.py` 调试输出）：`2w9w2t2t4t4t4t6t6t7t4b中白白` 各候选
   `s13 ∈ {1,2}` 而 `knock13 ∈ {2,3}`，逐候选都 ≥。
2. **`god_fan_boost` 近恒等于关**。`_fan_value = laizi*3 + (pairs≥4 ? pairs : 0) + triples`；
   同一手牌的候选之间**白张数是常数**（只有打白才变，而打白走财飘分支提前 return），
   实测该手牌 9 个非白候选里 7 个 `_fan_value` 完全相同（7,7,7,6,7,7,7,7,4）⇒ 没有可放大的信息。

**`baotou_slack=2, max=2` 的翻盘全部是「向听变差 1、sb13 不变」**，例：
`a_5b83c31e82d3 b0 r1 巡5 手牌=1w2w3w4t8t8t4b5b8b9b白 副露1`：base 打 `4t`（s13=0/sb13=2），
该臂改打 `5b`（**s13=1**/sb13=2）。**多花一档速度，白的位置一动不动** ——
这正是历史 `baotou_slack=2/2` 实测 **−0.455（z=−3.47）** 的机制解释。

### 3.5 差距发生在决策链的哪一环（结论）

| 环节 | 是否有差距 | 证据 |
|---|---|---|
| 早期路线（保不保白、打不打白） | **无** | 弃白率 我 **0.07%**（5/6916）vs 对手 **0.21%**（45/21083，人均同量级）；Δ≥1 双方 **100%** |
| 中期保白（出牌层的取舍） | **无** | D2 ①/② 机会 100% 抓住；D3 可改进点 1.1% |
| **中期「面子数」积累（鸣牌）** | **有，主因** | 碰转化 34.9% vs **68.2%**；副露均值全程 1.4~1.7×；m 每 +1 把 P(Δ≤1) 从 15% 推到 52% |
| 末期听型（白在不在将位） | **有，但是结果不是原因** | 我 98.4% 的带白听牌不是爆头；但出牌层无法改变（1.1%）⇒ 只能靠「进听前」的牌型 |

| **①** | **副露太少 ⇒ 爆头所需的「自然面子数」降不下来** | 碰机会 **722 次**（持白 308 次）我只碰 **252（34.9%）** vs 对手 **68.2%**；吃 35.4% vs 38.9%；碰/吃比 我 **0.64** vs 对手 **1.03**；胡牌面子≥2 我 23.3% vs 对手 40.2% | `[A]` 机制 + `[B]` 约 9300 次机会 |

| **③** | **七对路线占用**：我的对子偏多、面子偏少，正是七对分支的指纹 | 七对胡 **我 13/210 = 6.2% vs 对手 12/579 = 2.1%**（≈3×）；对子均值 2.46 vs 2.21（m0,s1） | `[B]` |
| **④** | **出牌层的「保白」tiebreak 空间 ≈ 0** | 能直接做出爆头听牌的机会 **18 次/800 局**，我 100% 抓住；零代价改进点 **31/2879 = 1.1%**；付向听也不行（1 例） | `[A]` 枚举全部候选 |
| **⑤** | **现有 genome 键无法触及这条路** | `knock` **0/800 翻盘（可证明 no-op）**；`god_fan_boost` 1.5/2/3 **0/800**；`slack2` **0/800**；`slack2max2` 10.4% 翻盘**全是净亏**；`fan_est=real` 4 例 sb 变差 | `[A]` |

**被证否的假设（写清楚，避免重复投入）**：
- ✖「我该多留白/少打白」——双方都不打白。
- ✖「我该在同向听内优先保爆头」——空间 1.1%，且引擎已经 99% 在做。
- ✖「我该在滑一档向听去保爆头」——`slack2max2` 10.4% 翻盘全是净亏。
- ✖「七对挤掉爆头」的方向要反过来：**不是七对占用资源，而是「对子多、面子少」这一共同原因**同时
  产生「七对率高」和「爆头率低」（③ 是 ② 的镜像，不是独立根因）。

### L1 · `bao_claim`：持白时放宽鸣牌门控 **【首选，机制最直接】**

- **位置**：`sim/players.py::Smart.want_peng` 与 `Smart.want_chi`（对应线上 `smart_bot.py` 的
  `should_peng` / `best_chi` 调用点，`smart_bot.py:525` 与 `:537`）。
- **判据**（新增 kwargs，全默认关 ⇒ 与现基线逐决策一致）：
  ```
  bao_claim        = False   # 总开关
  bao_claim_min_lz = 1       # 手里白 ≥ 该值才启用
  bao_claim_max_melds = 2    # 已副露 < 该值才启用（避免过锁）
  bao_claim_sb     = 1       # 要求鸣牌后 min_d shanten_baotou(h13_d, m+1) ≤ 该值
  ```
  逻辑：当 `bao_claim and hand[LAIZI] ≥ bao_claim_min_lz and melds < bao_claim_max_melds` 时，
  在**现有门控之外**追加一条通路：只要鸣牌后（任选一打）`shanten_baotou ≤ bao_claim_sb`，
  **就碰/吃**，忽略 `ukeire_gate` 与 `gate_max_shanten`。
- **依据（`data/_ob_claim.py` + `_ob_baotou.py N`）**：持白的**碰**机会 **308** 次里我碰 110、放过 198；
  **放过的 198 次中，若碰则 `sb≤1` 的有 54 次（27.3%，现状只有 7.1%），其中「不亏向听」140/198 = 70.7%**；
  最多能让 **9 次**直接变成爆头听牌（`sb=0`，乐观口径：允许为保 sb 多付 ≤1 向听）。
  持白的**吃**机会 450 次里吃掉 151、放过 299；**放过的 299 次中 36.5% 能让 sb 变好，103 次不亏向听**。
- **预期量级（诚实口径）**：
  - 持白碰转化 34.9% → ~60% ⇒ 多碰 **约 +85 次/800 局**（308 × 28pp）；
  - 换来 **+9 个直接爆头听牌、+45 个「离爆头 ≤1 步」**（上限口径）；
  - 爆头率 **7.1% → 9~11%（+2~4pp）**，场均番 **1.157 → 1.18~1.20**，
    按同位置折分口径 **+0.10 ~ +0.20 分/局**；
  - 代价：胡牌率可能 −0.5~−1.5pp（碰会减手牌灵活性）。**必须先看这两个指标一起动**。
- **验证**（同 run 带 `base_g`；`_BG` 纪律）：
  ```bash
  for i in $(seq 0 9); do python data/eval_run.py --run ob_claim \
      --configs base,base_g,bao_claim,bao_claim_sb0 \
      --field strong --shard $i --shards 10; done
  python data/eval_report.py --run ob_claim --field strong --base base_g
  ```
  主指标：Δ爆头率(pp)、Δ场均番；副指标：Δ胜率、Δ分。
  **所需局数**：目标 +0.10~0.20 分/局 ⇒ **3000~4500 局/臂**（先 1000 局筛方向，再用 holdout 确认）。

### L2 · `bao_plan`：把爆头当**第三向听路线**，但**必须与副露联动**

- **位置**：`mahjong/decision.py::discard_decision`，替换现有
  `baotou_route`（第 592~598 行）的窄门控。
- **为什么必须联动**：m=0 时 4 面子门槛太高（`Δ` 天生 2~4），强行走爆头 = 纯亏；
  m≥1 后门槛骤降。已有实测 `slack2max2`（**不看 m**）−0.455 就是这个原因。
- **判据**：
  ```
  bao_plan            = False
  bao_plan_min_melds  = 1    # 已副露 ≥ 该值才认为爆头路线可行
  bao_plan_max_sb     = 2    # 且 sb14 ≤ 该值
  bao_plan_giveup     = 3    # sb14 − s14 ≥ 该值时放弃该路线（回到纯 shanten）
  ```
  生效时 `s_map[d] = shanten_baotou(c, m)`（与今天 `baotou_route` 同一个机制，
  只是触发面从「sb≤1 且 Δ≤1」放宽到「m≥1 且 sb≤2」）。
- **预期量级**：把 D2 ③「离爆头听牌 ≤1 步」的机会从 **13.0% → 19%**（对齐对手），
  爆头率 **+2~5pp**；**风险**是付向听（`slack2max2` 的教训），所以 `bao_plan_giveup` 必须开。
- **验证**：
  ```bash
  for i in $(seq 0 9); do python data/eval_run.py --run ob_plan \
      --configs base,base_g,bao_plan,bao_plan_m2 \
      --field strong --shard $i --shards 10; done
  python data/eval_report.py --run ob_plan --field strong --base base_g
  ```
  另加一个**零风险前置探针**（不跑 sim）：统计合规的「m≥1 且 sb14≤2 且 Δ≥2」决策点数量；
  若 < 0.5 决策/局则直接结案（本次实测该口径的机会数见 `_ob_baotou.py D2 ③`）。

### L3 · `claim_bao_first`：让「碰」优先于「吃」去堆面子数

## 7. 方法与可信度

| 环节 | 校验 | 结果 |
|---|---|---|
| 四家手牌重建 | 789 局赢家终局张数 == 14−3×副露 | **789/789** |
| 重建异常（弃牌不在手 / 鸣牌牌不在手 / 副露含财神） | 逐条计数 | **0 条** |
| 爆头判据 | `any_draw_win(摸前13)` vs 服务端 `detail` | **162 = 162，100%** |
| 零和 | `round_ended.scores` 逐局求和 | 800/800 = 0 |
| 样本量告警 | 147 手爆头、18 个我的爆头听牌态 | 涉及**次一级分层**（如 m=3 的格子）时是**噪声级**，已在表中标 n |

**噪声级 vs 机制明确的划界**：
- **机制明确（可证明/全量枚举）**：`knock` 是 no-op；出牌层余量 1.1%；爆头听牌机会 18 vs 190；
  爆头形状 = (4−m) 面子 + 单白；Δ≥1 恒成立。
- **统计显著但需复测（n=800 真机）**：碰转化 34.9% vs 68.2%（722 vs 1908 次机会）；
  Δ≤1 40.2% vs 55.1%；爆头率交叉表的主要格子。
- **噪声级（不要单独下结论）**：m=3/4 的格子（n<20）、`seven` 形（10 手）、
  单场次差异（`docs/postmortem-2026-09-22.md` 已证单场 net 的 sd≈106 分）。

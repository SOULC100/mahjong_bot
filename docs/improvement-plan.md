## 0. 一页结论

### 0.1 三条主线（按性价比排序）

| 优先 | 主线 | 一句话 | 量级依据 |
|---|---|---|---|

### 0.2 对旧文档最重要的修正：**番型路线不是主线，速度才是**（实测）

旧文档（`rules-strategy.md §6`）的判断是：「EV ∝ f×(p−0.25)，真机场均番型只有 1.05 → 最大空间在把已经能赢的牌换成更大的番（弃胡打财飘 E1）」。

**实测结论：番型的"机会频率"被规则卡死，E1 的收益上限 ≈ 0.005 番/局，可以忽略。**

| 路线机会 | 非 YCB（1000 局） | YCB（1000 局） | 含义 |
|---|---|---|---|
| **财飘机会**（爆头态摸白 + 手留白） | **0 次** | 8 次（≈8/千局） | 旧文档的"最大杠杆"实测只在 YCB 下偶发，且兑现上限 ≈ +0.012 番/局 |
| `should_piao` 出牌点（4面子+2财神） | 0 | 14/千局 | 同上；这条分支本身就是"已经能胡" |
| 爆头态摸牌 | 0.027/局 | 0.29/局 | YCB 下才常见（YCB 只能靠爆头/杠开胡） |
| 明杠可做（全场/局） | 0.199 | 0.324 | 单人 ≈ 0.05~0.08/局 |
| 补杠可做 | 0.002/局 | 0.003/局 | 可忽略 |
| 暗杠可做（单人/局） | 0.040 | 0.074 | 低 |
| 天胡（庄家发牌即胡） | **0 / 1000** | **0 / 1000** | 白丢的胡几乎不会出现 |
| 七对形占胡牌比 | 5.5% | 6.4% | 与真机 42 局（4.8%）**吻合** |
| **场均番型（每个胡牌）** | **1.099** | **1.530** | 非 YCB 与真机 1.098 几乎一致 |
| **每局期望番型** | **1.089** | **1.302** | YCB 把番型抬高 ~20%，但"有胡的局"从 99.1% 降到 85.1% |

> **两条推论**
> 1. **番型杠杆的"供给"是结构性的**：财神只在约 20% 的出牌点出现（`laizi_0` 占 68~75%），
>    而飘/爆头/七对都需要极特定形态 → 非 YCB 下场均番型天花板就在 1.1 附近（YCB 约 1.5）。
>    即使把**所有**已测路线的机会 100% 变现，对每局期望番型的增量也只有 **+0.01~0.02 番**
>    ≈ **+0.01 分/局**；而 **+1pp 胜率 ≈ +0.13~0.34 分/局**（闲/庄）。差 10~30 倍。
> 2. **主导杠杆仍是 p（在墙内做成牌），而且比赛比想象的更短**：
>    4×冠军自对弈平均只有 **34.2 个出牌点/局**（人均 ~8.5 次摸牌）就分胜负；
>    真机归档 12 局实测同样量级（353 次 `tile_drawn` / 12 局 ≈ 29 次摸牌 + 3.9 次鸣牌/局 ≈ 8.3 回合/人）——
>    **牌墙通常根本没摸空**（自对弈流局率仅 0.9~7.9%）。
>    只有对手"完全不鸣牌"时牌墙才会被摸空：1 Smart vs 3 弱基线实测 52% 胡牌率 / **42.5% 流局**。
>    → **速度的边际价值极高**（每早一巡 ≈ 赛跑时间的 1/9），而「赢家里只有 50~54% 是最先听牌的」
>    说明领先之后**听口宽度/落地质量**才是分水岭。

## 2. 实测证据

### 2.1 路线机会频率探针

```
python data/_route_probe.py --games 200 --shard N --no-report     # N=0..4，YCB 开
python data/_route_probe.py --merge                               # → data/_route_report.txt
python data/_route_probe.py --games 200 --shard N --tag noycb --no-ycb --no-report
python data/_route_probe.py --merge --tag noycb                   # → data/_route_report_noycb.txt
```
探针**不改任何策略代码**：用 `Game`/`Smart` 的子类 + 钩子只读观测（`_can_win`/`_win_result`/`_discard`/`_deal`/`_resolve_claims`）。
数字见 §0.2。**方法学提醒**：4×冠军自对弈的"胜负率"是 25% 对称场，不能当实力指标；只有**路线频率**可用。

### 2.2 线上/离线 `remain` 口径探测

```
python data/_parity_probe.py --games 60 --shard 0
```
对同一批真实中局状态（**场上至少有 1 副露**的出牌点）分别用三种 `remain` 调 `discard_decision`：

| 对照 | 出牌不同比例（2 分片 × 70 局，**3913 个出牌点**） |
|---|---|
| sim 口径（原始张数 + 含副露） vs 线上口径（比例缩放 + 不含副露） | **136 / 3913 = 3.48%** |
| sim 口径 vs 修复版（比例缩放 + 含副露） | **0%**（缩放本身不改排序） |
| 线上口径 vs 修复版（= 副露漏算的净影响） | **3.48%**，且 100% 发生在**打后向听相同**（纯 tiebreak 被输入口径翻转） |

→ **结论**：①均匀缩放**不改变**排序（印证 README 旧结论）；②真正的分歧只有**副露漏算**，
修法就是 `_recalc_remain` 的 `visible` 加上 4 家副露（3 行代码）。
原始输出：`data/_parity_report.txt`。

### 2.3 内存（可用性）

```
python -B -c "... discard_decision ×40 on random hands ..."    # → 257 MB / 40 决策
python -B -c "... 6 局 4×Smart ..."                            # → _mp 109 万条（≈450 MB）
```
`shanten._best/_mp` 是 `@lru_cache(maxsize=None)`：实测**每局 +15~20 万条**。
`sim_ab*.py` 每 100 局清一次，**线上从不清理**；探针并行 10 进程时总内存一度 **38 GB**（清理后回落到 6~9 GB）。
长赛程（M=10 × Rounds=8 单进程）下这是**丢局级风险**。

sim（非 YCB、4×冠军自对弈）与**真机 42 局**对齐得很好：

## 4. P1 —— 策略路线（按实测收益重排）

### 4.1（P1-a）修 `ukeire_depth`：唯一直接打在主导杠杆 p 上的结构性改动 —— **机会已实测，比预期小**
- **现状**：`ukeire_depth`（一步前瞻）对「打一张即上听」的候选恒返回 0（`ukeire.py:88-93`：它要求
  `shanten_after_discard(c2,d2) == s2`，而进张的 s2 = −1，13 张手牌永远不为 −1），且极慢
  （审计实测 45,572 次 shanten 调用 / ~6.9s 一次决策）→ 线上关着（`USE_DEPTH=False`）。
- **盲区准确位置**（先纠一个常见误解）：打牌**不会**降低向听（向听只在摸牌时降）。
  出牌引擎在「打出去就听牌」时用的 `ting_count`，**已经**考虑听口宽度；
  真正瞎的是**上一手**：打出去仍停在向听 1 的候选，只用 `ukeire_quality`（进张数，权重恒 4），
  **看不见「摸上听之后听多宽」**——同样 8 张进张，落进 3 张听的愚形还是 8 张听的两面，分数一样。
- **机会大小（2026-09-20 实测，`data/_wait_opportunity.py` + `data/_wait_opportunity.txt`）**：
  400 局 / **3,692 个「向听=1 且打一张仍停在向听 1」的出牌点**，比较
  ①现引擎的 `ukeire_quality` 排序 ②两步期望（进张 × 落地听口宽度）：

  | 指标 | 实测 |
  |---|---|
  | 两者选的**不是**同一张 | **166 / 3692 = 4.5%** |
  | 其中两步期望高出 ≥50% | 35（0.9%） |
  | 选错时的平均差距 | ≈14.9（两步期望值，典型量级 20~60） |

  例：`4w6w8w8w 1t2t2t4t6t7t8t 1b1b 白` —— 现引擎选 8万（进张质量 60，与 1条/4条并列，靠池序取先），
  两步期望选 1条（42.25 vs 40.25）。**典型差距只有几个百分点**，不是"3 张听 vs 8 张听"那种灾难。
- **结论（修正我此前的乐观估计）**：机会是 **4.5% 的向听=1 出牌点、平均差几个百分点**
  → 折算到胜率**大概率在 0.1~0.5pp 量级，不是我先前说的 ≥1pp**。
  实现本身仍便宜、风险低（只在**同一向听层内**重排，不会让手牌慢一档），
  所以**建议排在 P0 之后做**，不要为它推迟部署对齐与可用性修复。
- **建议实现**：不要修那个 O(n²) 深搜，改成**便宜的解析式**：对 `s_map[d]==1` 的候选，
  把权重里的常数 4 换成与落地听口成比例的量（`ting_count(摸 t 后)/4`），即"进张 × 落地听口宽度"，
  只在 base==1 层展开（`_mp` 缓存 + 有界缓存）。
- **验证**：配对 z + ≥2 seed；速度类候选可"候选 vs 3 冠军"看相对胜率，另报"vs 3 弱基线"的平均分。

### 4.2（P1-b）鸣牌阈值：**2026-09-21 冻结基准实测 + 已晋级**（结论与旧文档相反）
- **机制**：鸣牌 = 用一次摸牌换一张**已知且有用**的牌（自己少摸 1 张，这张留给后面的人）。
  真机 12 局实测：每局 3.8 次鸣牌 / 29 次摸牌；回合数守恒 `回合 = 摸牌 + 鸣牌` 对得上。
  → 在"人均 ~8.3 回合就分胜负"的短赛跑里，一次鸣牌能省下一整巡，代价相对小。
- **实测（1000 局冻结基准 + 2000 局 holdout，合并 3000 局配对，见 `docs/eval-rounds.md`）**：
  | 方案 | Δ分 | z | Δ胜率 | z |
  |---|---|---|---|---|
  | `both_gate`（吃+碰都开 `ukeire_gate`）**已晋级** | **+0.326** | +3.42 | **+1.27pp** | +2.47 |
  | `peng_gate`（只开碰） | +0.191 | +3.16 | +1.03pp | +3.03 |
  | `claim_le1`（只在向听 ≤1 鸣牌） | **−0.727** | −2.75 | −2.90pp | −2.56 |
  | `wait_full`（听口宽度全量替换） | −0.634 | −3.31 | −2.40pp | −3.22 |
  | `claim_wall24`（墙 <24 停鸣牌） | 0.000 | 0.00 | 0.00 | 从不触发 |
- **结论**：**放宽**鸣牌（向听不变但进张质量提升也鸣）**大幅为正**；
  **收紧**鸣牌（按向听门禁）**显著为负**；终盘门控在本规则下无用（对局结束时墙还剩 ~40 张）。
  ⚠️ 这**推翻了旧文档「A1 吃碰 ukeire 门控 → 证伪」**：旧测是单 seed + 硬编码阈值 + 无配对，
  病根在评估方法，不在门控本身。
- **上线**：`smart_bot.CLAIM_UKEIRE_GATE=True`（`CLAIM_GATE_MAX_SHANTEN=1`）+ `opt/champion.json`
  的两个 gate 置 true + `game_state._recalc_remain` 补副露（门控输入口径必须与 sim 一致）。
- **遗留**：真机 `live_smoke`/`verify_live` 尚未跑；两半均衡性上 `peng_gate` 更稳（退守路径）。

## 0. 冻结基准（不许改；要改就升 version 并重跑全部基线）

| 项 | 值 |
|---|---|
| 种子 | `data/eval/seeds_1000.txt`：`seed[i] = 20260920 + i`，i ∈ [0,1000)，**顺序固定** |
| 种子哈希 | sha256 `ee0e62a0304e0375f04baf9c9e117db3dfdc4a02638e7f00b4540dae14bb4ebd` |
| 规则 | `youcai_bikao=False`（真机测试房口径）；见 `data/eval/spec.json` |
| **庄家** | `seed_index % 4`（**确定性轮庄**）：1000 局里四人各当庄 250 次，且同一 seed 下**所有方案庄家相同** → 配对不被庄家漂移污染。平台真实规则「赢家坐庄」留给 P0-9 真机校验 |
| 座位 | seat0 = 被测方案，seat1-3 = 场地对手 |
| 强场（主） | 3 × `data/eval/field_champion.json`（冻结时刻的冠军）→ 测**相对实力**，基线胜率 ≈ 25% |
| 弱场（参照） | 3 × `Baseline()`（永不鸣牌）→ 测**绝对胜率**，基线胜率 ≈ 50% |
| 主指标 | **配对 Δ平均分**（同 seed 同庄家，逐 seed 求差 → mean/se/z） |
| 次指标 | Δ胡牌率(pp)、场均番型、流局率；另报前 500 / 后 500 局**分半复现** |
| 判定 | z ≥ 2 **且**两半同号 → 晋级候选；z ≤ −2 → 疑似有害；否则噪声 |

**为什么配对**：同一 seed = 同一副牌墙、同一庄家位；逐 seed 求差能消掉绝大部分方差，
比两个独立样本灵敏得多。**为什么 z 而不是固定阈值**：历史 `sim_ab*.py` 用硬编码 `Δ≥0.8`
单 seed 门槛，等于拿噪声当信号（旧文档自己都复验不过）。

复现：
```bash
python data/eval_freeze.py                 # 冻结（已跑过；--force 会重建基准）
python data/eval_run.py --list             # 看有哪些候选方案
# 10 个分片并行（沙箱禁 multiprocessing，用分片代替）
python data/eval_run.py --run r1 --configs base,<方案...> --field strong --shard K --shards 10
python data/eval_report.py --run r1 --field strong --append-ledger
```

5. **番型/EV 类改动依旧中性**：`fan_fix` +0.018、`no_ev` −0.015 → 再次印证「向听/速度主导」。

**⚡ 本轮最重要的发现：权重类旋钮在这套决策结构里几乎是惰性的。**

逐决策点验证（475 个真实出牌点，`data/eval_run.py` 之外的直接对照）：

| 改动 | 改变的决策数 |
|---|---|
| `ukeire_w` 0.1 → 0.05 / 0.2 | **0 / 475** |
| `ukeire_w` 0.1 → 0.5 / 1.0 | 2 / 475 · 83 / 475 |
| `fan_weight` 5 → 2 / 8 / 20 | **0 / 475**（4 倍变化也没影响） |

原因（读代码即可解释）：
1. `bound = min_s + 1` 把候选限制在「同向听 ±1」，主导项 `向听 × 100` 先把排序定死；
2. **同一向听层内，如果所有候选的 `_fan_value` 都是 0**（大多数中局手牌没有财神/刻子，`_fan_value` 就是 0），
   那 `score = −ukeire×ukeire_w`，**对单个权重做等比缩放不改变 argmax**；
3. `fan_weight` 要起作用得先有 `_fan_value ≠ 0` 的手牌 → 中局大多数时候它乘的是 0。

→ 这补上了旧结论「向听数完全主导决策」的**机制解释**：不是权重调不动，而是**权重在多数状态下乘的是 0 或不参与排序**。
也解释了为什么历史优化器在权重维度上爬山爬不出东西。**结论：不要再把算力投在权重微调上**，
要提升就得改「参与排序的量」（如本轮胜出的鸣牌门控、P1-a 的听口宽度）。

### 20.2 发现的 bug：拆面子漏了「财神补顺子下沿」

线上 98 局里有 **2 局的番型对不上**（本地算 `fan=1`、服务器 `fan=2`，服务器 detail 含"爆头"）。
根因定位到 `mahjong/shanten.py::_mp` 与 `mahjong/win.py::_can_meld` 的**顺子枚举不完整**：

- 旧版只枚举「以**最低现有牌** i 为起点」的顺子（`i, i+1, i+2`，缺的用财神补）；
- 于是「手持 `8筒 9筒` + 财神 → 财神当 `7筒` 成 `789筒`」这种**财神补下沿**的拆法完全没被枚举，
  被降级成"两面搭 +1" → 向听数高估 1；
- 线上实证牌型（已副露 2 摊）：暗手 `2万3万4万 7筒8筒9筒 白`，摸 `7筒`
  （拆法 = `234万` + `789筒`（白当 7筒）+ 将 `7筒7筒`）→ 旧版 `any_draw_win` 判 False ⇒ 爆头 ×2 漏判。

**影响面比"少算番"严重**：线上 `smart_bot.can_hu()` 的判据就是 `shanten(hand, melds) == -1`，
所以这类牌型下 bot 会**把胡牌打掉**（一次漏胡 = 丢掉一整局的胡 + 让对手继续跑）。
`can_win`（`win.py`）有同一个洞，`fan._is_four_melds` 也走它。

## 22. R15（2026-09-25）：吃额度该留给哪副搭子？—— **"先消化补不上的搭子"晋级（+0.265）**

用户提出的假设（原话）：
> 「吃两摊的限制，应该考虑比如还差 3 手吃张听牌的时候，应该放弃进张数多的吃，只有进张数少的搭子才去吃」

### 22.1 先量化"被吃掉的是哪副搭子"（`data/_chi_budget_probe.py`，80 局 200 次吃）

定义：某副搭子的**剩余进张** = 组成顺子还需要的第三张里，除去**刚被打出的这张**后仍未见（）的张数。
（两张手牌组成的搭子，剩余进张结构上 ≤ 4：两面另一端最多 4 张。）

| 剩余进张 | 次数 | 含义 |
|---|---:|---|
| **0** | **96（48%）** | 这张弃牌是唯一成顺机会 —— 不吃这副搭子就废了 |
| 1 / 2 | 3 / 8 | 近乎死搭子 |
| 3 | 26（13%） | 两面，另一端只剩 3 张 |
| **4** | **55（27.5%）** | 两面且另一端 4 张全活 ← **用户说的"进张数多的吃"** |

- 按向听拆：**向听 ≥3 的吃占 63/200 = 31%**（≈0.8 次/局），其中 **25 次（40%）消耗的是还剩 3~4 张的宽搭子** → 目标约 0.3 次/局。
- **多解漏点**：同一张弃牌有 ≥2 种吃法时（61 次），只有 **61%** 挑了最窄的搭子，**39% 先消耗了更宽的搭子**。
- 额度绑定（§21 修正后口径）：5 次/80 局 = 62.5 次/1000 局。

### 22.2 实现（新增两个旋钮 + 一个口径修正）

| 旋钮 | 语义 |
|---|---|
| `chi_narrow_max_accept` + `chi_narrow_min_shanten` | 向听 ≥ 阈值时，**只吃**剩余进张 ≤ 阈值的窄搭子（= 用户字面规则） |
| `chi_prefer_narrow` | 同一张弃牌多解时，**先消化"自己摸不进来"的那副搭子**（排序：吃后向听 → 剩余进张 → 吃后进张质量） |
| `accept_remain`（口径） | 剩余进张是**绝对张数**判据 → 必须传**原始未见张数**：sim `remain_estimate`（4−visible）与新增 `GameState.raw_unseen` 同口径；线上 `state.remain` 是按牌墙缩放过的（≈0.47×），直接拿它比阈值会让同一个数在线上/离线含义不同 |

代码：`mahjong/tiles.py::pair_completions()`、`mahjong/decision.py::best_chi(..., narrow_max_accept, narrow_min_shanten, prefer_narrow, accept_remain)`、`mahjong/game_state.py::raw_unseen`、`sim/players.py` 三个旋钮、`data/eval_run.py` 四个方案、`tests/test_chi.py` + `tests/test_smart_bot.py` 用例。

### 22.3 结果：**假设被拆成两半——诊断对，字面规则错**

| 方案 | 发现集 r15（1000 局） | 确认集 h9（2000 局新种子） | **池化 3000 局** | 判定 |
|---|---|---|---|---|
| `chi_narrow3`：向听 ≥3 不吃宽搭子（**用户字面规则**） | +0.484（z=2.61） | **+0.021（z=0.14）** | +0.175（z=1.54，后半 +0.021） | ❌ 选择效应，不晋级 |
| `chi_narrow2`：向听 ≥2 就只吃窄搭子 | +0.403（z=1.94） | 未测 | — | ❌ |
| **`chi_prefer_narrow`：多解时先消化窄搭子** | +0.392（z=2.41） | **+0.202（z=1.61）**，分半 +0.233/+0.170 | **+0.265（z=2.66）**，分半 +0.279/+0.251 | ✅ **晋级** |
| 两者组合 | — | +0.008（z=0.06） | +0.008 | ❌ 互相抵消 |

- 三个方案都把**场均番 1.108 → ≈1.170**（少鸣无用牌 ⇒ 保留门清/七对路线）；`chi_prefer_narrow` 另把胡牌率 25.5% → **26.2%**。

  又保留后续进张宽度。
- 部署：`smart_bot.py` 新增 `CHI_PREFER_NARROW=True` 并传入 `should_chi(..., prefer_narrow=...)`；
  `opt/champion.json` 同步加 `chi_prefer_narrow: true`（线上 = 冠军）。全部测试绿、漂移哨兵逐位一致。

**靠张重叠只算一次** —— 真机那一手：留 `2w` 独占 8 张（`1w/2w/3w`，`4w` 已被 `6w` 覆盖）< 留 `9t` 独占 10 张
⇒ 引擎先打 `2w`（打后 72 张 vs 打 `9t` 的 70 张）。用户假设若想成立，必须证明边张在 ukeire 之外还有额外代价。

**做法**：`edge_w` 偏置开关（`decision.discard_decision(..., edge_w=)`；1/9=3 分、2/8=2 分、3/7=1 分，
同向听内重排，≈0.1 分 = 1 张进张），三档一起上冻结基准配对 A/B（强场，1000 seeds × 10 分片）。

| 方案 | 局数 | 平均分 | 胡牌率 | 场均番型 | Δ分(配对) | z | Δ胜率(pp) | z | 前半/后半 Δ分 |
|------|-----:|-------:|-------:|---------:|---:|---:|---:|---:|---|
| `base`（现冠军） | 1000 | +0.19 | 25.2% | 1.091 | — | — | — | — | — |
| `edge1`（w=1，约能翻转「进张差 ≤10 张」的平手点） | 1000 | −0.07 | 24.0% | 1.163 | **−0.260** | −0.69 | −1.20 | −0.82 | −0.126 / −0.394 |
| `edge3`（w=3） | 1000 | −0.43 | 22.5% | 1.160 | **−0.621** | −1.63 | −2.70 | −1.79 | −0.558 / −0.684 |
| `edge10`（w=10，近乎无脑先打边张） | 1000 | −1.09 | 19.4% | 1.155 | **−1.275** | **−3.31** | −5.80 | **−3.90** | −1.356 / −1.194 |

**判定：证伪**（不进确认集）。三条证据：① 三档**全为负**且**前半/后半同号**；② 呈**剂量-反应**关系
（w 越大越差，w=10 时 z=−3.31 显著）；③ 机制自洽——边张优先把**胡牌率**从 25.2% 压到 19.4%（手更慢），
只把赢下来的手做得稍大（场均番 1.091→1.155），而 EV ∝ 番型 × (胜率 − 0.25)，速度损失远大于番型收益。
那「8 张 vs 10 张」的独占进张差额，正是引擎**已经算对**的东西，人为加偏置只会把它算错。

一、对战规则

1.1 平台固有规则（所有锦标赛一致）

• 牌具：136 张（万/筒/条 1-9 各 4 张 + 东南西北中发白各 4 张），无花牌；白板 = 财神（百搭），可替代任意牌。

• 财神限制：财神本身不能被吃、碰、杠、胡，可主动打出；打出财神那一圈（抓打圈）：其余玩家不能吃、碰、明杠（仅暗杠与自摸胡），出牌只能打刚摸到的牌。打财神者本人不受此限（可吃碰明杠、可任意出牌）——圈内吃碰后再打财神 = 财飘链 +1（圈以本人为新打财神者重启），打其他牌 = 链断且圈解除（2026-09-08 裁定）。

• 胡牌：只能自摸，不允许点炮；禁止抢杠胡。

• 连庄：直上三连庄——首局即按 ×8 计（不从平庄 ×2、二连庄 ×4 递增）；流局庄家连庄。

• 牌墙：最后 10 墩（20 张）保留不摸；最后 10 墩之内禁止杠牌；摸完无人胡则流局。

• 吃碰：吃最多 2 摊（服务端强制：本局已有 2 组吃副露后再吃被拒，409）；碰、杠不限次数；碰（含明杠）窗口先于吃窗口。

1.2 胡牌判定

• 普通胡：4 组面子 + 1 对将（面子 = 顺子 / 刻子 / 杠）；吃碰杠折算（吃最多 2 摊）。

• 七对子：7 个对子，禁止吃碰明杠暗杠；财神可补对；可财飘（2026-09-02 修订：七对与飘/杠链叠加计番；杠因副露与七对互斥）。

• 爆头：听牌态摸任意 1 张牌上来即胡（财神数不限，支持副露；正好 4 张白板亦按此判定——4 白听任意即胡时计爆头并与「4 个白板 ×2」叠加，2026-09-07 修订）。

• 弃胡：摸牌后不强制自动胡——客户端自行判胡（快照无 allowed_actions），可提交 hu，也可弃胡打牌（飘/杠链前提）；可胡但超时未响应 → 服务端自动胡兜底。

1.3 番型倍率（在自摸基础上连乘）

总番 = 1 × 分支因子 × 2^动作链次数 ×（4 白板 ×2）×（爆头 ×2）；计算顺序：分支 → 动作链 → 4 白板 → 爆头（最后统一加）。

 | 番型 | 说明 | 倍率

 | 平胡 | 普通自摸胡，无财神特殊状态 | ×1

 | 七对子 | 7 对胡牌 | ×2

 | 豪华七对 | 七对含 1 组四张（4 张真白板在其余牌全为自然对、未用于补落单时也算 1 组；白板已作百搭补配其他牌成对时不重复计豪华） | ×4

 | 双豪华七对 | 七对含 2 组四张 | ×8

 | 三豪华七对 | 七对含 3 组四张 | ×16

 | 杠开 | 杠后补的那张牌直接自摸胡（杠上花）= 链 1 动作 | ×2

 | 杠爆 | 爆头状态下杠，杠补牌胡 = 爆头 × 杠开 | ×4

 | 财飘 | 爆头状态打出财神继续听任意牌胡 = 爆头 × 飘 1 动作 | ×4

 | 双财飘 | 连续两次打出财神再爆头胡 | ×8

 | 三财飘 | 连续三次打出财神再爆头胡 | ×16

 | 4 个白板 | 胡牌时手牌留存 + 链内飘出的白板 = 4（正好 4 张；普通打出的、杠出的不算） | ×2

 | 爆头 | 见 1.2 判定（最后统一加；正好 4 白板除外） | ×2

• 动作链：飘与杠可连续、可组合，每个飘/杠动作 ×2（杠飘组合叠加计算）；打出非飘非杠的牌（含非爆头态打白板）→ 链断重新计数。

• 爆头摸到白板：可提交 hu（爆头 ×2）或弃胡打白飘（博财飘 ×4 起）——策略权衡由 AI 决定。

• 七对也可以爆头（七客 / 豪华七客）：如 6 对 + 1 财神单吊 = 七对 ×2 × 爆头 ×2 = ×4。

• 平胡分支最大牌型：3 连杠 + 三财飘 + 爆头 + 4 白板 = 2⁶ × 2 × 2 = ×256。

• 全局最大（2026-09-02 修订）：三豪华七对 + 三财飘 + 4 白板 + 爆头 = ×16 × 2³ × 2 × 2 = ×512——七对形爆头听牌（3 组四张 + 1 白）弃胡飘可达。

1.4 计分公式

得分 = 底分 × 胡牌番型倍率 ×（庄家 ×8 / 闲家 ×1），三家分别结算：

• 庄家胡：三家闲家各付 底分 × 倍率 × 8

• 闲家胡：庄家付 底分 × 倍率 × 8；另外两个闲家各付 底分 × 倍率 × 1

1.6 锦标赛可变参数（以 API 返回为准，不可写死）

        注意：底分、局数、同时场数 M、有财必拷响、碰/吃/出牌窗口等由创建者配置，每场锦标赛可能不同——机器人必须以 GET /api/tournaments/me/rules（或 GET /api/tournaments/{id}）返回的 config 为准。

config 字段含义：

 | 字段 | 含义

 | M | 每人同时参赛场数上限（该锦标赛内）

 | Rounds | 每场比赛的局数

 | BaseScore | 底分（计分公式的底分）

 | YouCaiBiKao | 有财必拷响（手上有财神时不允许平胡，必须爆头/杠开才能胡）

 | PengTimeoutSec | 碰窗口（默认 1s，固定走满防时间侧信道）

 | ChiTimeoutSec | 吃窗口（默认 1s，固定走满）

 | DiscardTimeoutSec | 出牌思考（默认 3s；可胡时超时自动胡，否则超时自动打出最右一张牌）

 | StartAt | 开赛时间（unix 秒）

 | RegisterDeadlineAt | 报名截止（unix 秒；0 = 无截止）

二、API 参考（玩家 API）

认证：所有玩家 API 均需请求头 Authorization: Bearer <令牌>。令牌来源（v24 起，POST /api/users 匿名注册已删除）：门户「报名」/「测试房间」派发参赛令牌（scoped，绑定具体锦标赛，仅显示一次）或门户「我的 AI 身份」签发全局令牌（首访明文一次、可轮换）；运营/验收另可经管理面造号端点取得绑定全局令牌。服务端只存令牌的 SHA-256，丢失只能重新生成。例外：§2.5 的测试房间数据 API 免认证（房间 id 即凭证，每房间独立限速 5/s + 每来源总量兜底 1000/s）。

 | 端点 | 方法 | 用途

 | /api/me | GET | 我的信息：user_id + 令牌绑定的 tournament_id（报名令牌；全局令牌为空串）+ 进行中比赛列表 active_games

 | /api/tournaments/me/rules | GET | 当前令牌绑定锦标赛的规则 config（报名令牌直达，无需锦标赛 id；全局令牌返回 400 TOKEN_NOT_SCOPED）

 | /api/tournaments/me/ready | POST | 到位（报名令牌直达；全局令牌返回 400 TOKEN_NOT_SCOPED）

 | /api/tournaments/{id}/register | POST | 报名（开赛前；幂等；校验同时 16 场上限）

 | /api/tournaments/{id}/ready | POST | 到位（开赛前；幂等；须先报名）。新建赛事分桌只认开赛时刻 ≤90s 内有已认证请求者（连上又断开会被剔除）

 | /api/tournaments/{id} | GET | 锦标赛状态：status / config / 报名与 ready 人数 / 我的比赛 my_games / ranking 排名 / voided 原因（仅参赛者可查）。多阶段锦标赛另含阶段字段组（stage / stage_status / stage_crashed / qualified / qualify_role）——见 §2.6

 | /api/games/{id}/state?seq=N | GET | 长轮询状态与事件流：seq=0 返回全量快照（含你的手牌、座位 seat、窗口成员 responding_seats 等自主决策字段）；seq=N 返回 N 之后的新事件；无新事件时挂起最多 30s 后返回 {"pending":true}；seq 落后当前局（round_ended 后新局已发牌、不产生事件）→ 立即返回全量快照（gap:true）

 | /api/games/{id}/notify | GET | SSE 通知流（v12 起，服务器推送）：连接即收初始帧 {"seq":N}（当前事件水位）；此后每次状态变更（出牌/摸牌/吃/碰/杠/胡/流局/超时等任意事件）推 {"seq":新水位}——帧只含 seq 信号，不含变化内容；每 30s 一行 : keepalive 维持连接；场终/死场推 {"seq":N,"closed":true} 后关流。收帧后按需 GET /state?seq=本地 拉增量（跨局/落后>256 自动回全量快照）。每用户 32 并发连接（429），不占 /state 的 16/s 频率额度

 | /api/games/{id}/action | POST | 提交动作：{"action":"discard|chi|peng|gang|hu|pass","tile":"1w"}——服务端纯验证：合法即执行、不合法 409（动作合法性客户端自研判定，快照无 allowed_actions）；吃可附加 "tiles":["1w","2w"] 指定用哪两张手牌吃（多组合时可选择），缺省服务端取第一组可行顺子

 | /api/match | POST | 自动匹配建房与入席（v13 起，全自动）：用全局 token——仅收门户绑定身份（「我的 AI 身份」签发或管理面造号；存量匿名全局令牌 403 PORTAL_BINDING_REQUIRED，v24 起；报名令牌 400 TOKEN_NOT_SCOPED）。服务端从自动匹配池（只含系统按默认配置自动创建的自动房，kind=auto）按就绪席多、开赛早者优先选房入席，无可兼容候选则自动建新房并把你作为首位入席——成功返回 {room_id, config, round_no}，之后用同一全局 token 照常参赛（GET /api/tournaments/{room_id} 的 my_games 发现场次、/state 轮询、/action 出招）。等待期重复调用幂等返回原房，绝不双房双席。body 可选 {"M":10,"Rounds":8}（小写键亦收）声明可承受上限（≤ 过滤——上限须 ≥ 服务默认；缺省/键 ≤0 = 不限）；显式上限低于服务默认（M=10、Rounds=8，v15 起）→ 404 NO_ROOM_AVAILABLE（永久条件，不重试）。满 4 人即开 M=10 场并发对局 × 每场 8 局（同一 4 人、座次逐场重洗，最晚场终后结算——单会话样本 80 手/人）。整场打完（finished 约 60s 宽限）自动房自动关停，玩家 API 对该房一律 404——赛果以最后一次 /state 快照与门户复盘为准；再打重调本端点（每次新会话新房）。限速 10 次/分/用户。管理员可在正式比赛期间关闭自由匹配（v29）：此时新的匹配请求返回 403 FEATURE_DISABLED（永久条件，勿重试）——已在房中的用户重调仍 200 返回原房，进行中的对局照常打完

 | /api/test-rooms/{id}/games | GET | 测试房间局列表（免认证）：[{batch, game_id, status}]，batch 升序——每局结束即可按需拉取（跨轮房间含全部轮次历史）

        from/to = 上一期窗口 [from, to)（北京时间切界，
        to 恒等于本期窗口起点、为排他上界）；me_uid = 请求者自身 user_id
        （本期无战绩、主榜 me 为 null 时仍可定位本人行——前端只按
        user_id === me_uid 高亮，禁止按 name 匹配）；top ≤4 行、字段与主榜行
        同形（rank/user_id/name/rooms/firsts/score）。三态：period=all →
        prev:null；上一期零对局 → prev.top:[]（空数组，非 null）；否则 ≤4 行。
        streak（可选整数，仅 rank=1 行且 ≥2 时出现）= 该用户从上一期起连续为「该期第一名」
        的期数（含上一期本身；某期全平台零 auto 房结算 = 空档即断，换人亦断），前端渲染
        「👑 连续 N 日霸榜」/「👑 连续 N 周霸榜」徽章。显示值为回退上限（日 60 / 周 8），触顶显示
        精确上限值——可能低于真实连续数。主榜 top/me/限速/no-store 语义零变化。

2.1 协议要点（AI 接入必读）

• 快照规范：seq=S 的响应已包含全部 ≤S 的事件，快照是规范真相；客户端局面 = 快照 + 后续增量事件（事件带自身 seq，校验连续性）；跨局落后返回的快照同样规范（含新局 round_no/phase/my_hand）。

• 失步恢复：发现缺口（响应含 gap:true）或动作 409 后，用 seq=0 重建全量快照。

• 跨局边界（v10 起）：每局结束（round_ended）后新局自动发牌不产生任何事件——事件流在新局首个动作前为空，庄家第 14 张为发牌直抽、无摸牌事件。此时继续用上一局末的 seq 轮询会立即收到新局全量快照（gap:true，含你的新局手牌 my_hand/round_no/phase），不会挂起至庄家出牌超时自动出牌；新局手牌一律以快照为准。

• round_ended 自带局号/庄键（v19 起）：每局结束的 round_ended 事件——胡牌（draw:false）与流局（draw:true）同款——携带 round_no（本局局号，1 基）/ dealer（本局庄家座）两键，按序消费无需自行推导；纯加性负载，旧 bot 忽略未知键零影响（新键可作复盘/统计/跨局对账依据）。

• 通知流（v12 起，可选）：不想高频轮询 `/state` 发现他人动作，可开 `GET /api/games/{id}/notify` SSE 流：收到 {"seq":N} 帧后对比本地已消费 seq，落后则 GET /state?seq=本地（快照/gap 语义不变），不落后丢帧即可；帧不含牌面/动作，牌面仍须按需拉取。游标纪律：/state 的 seq 参数语义 =「N 之后的事件」——游标永远是本地已消费 seq，初始帧的 seq 是包含式水位（服务器已发到 N），不可直接当轮询游标（会跳过之前全部事件）；游标未知请 seq=0 拿快照起步。

• 私有信息：事件流只含自己的摸牌；他人手牌绝不出现。

• 超时兜底：出牌思考超时——可胡时服务端自动胡（弃胡兜底，不丢番），否则自动打出最右一张牌；碰/吃窗口固定走满（防时间侧信道；抓打圈内窗口只对豁免方开放，同样固定走满）——AI 无响应比赛不会卡死，但积分损失不可避免。

• 自研动作判定（v2 起，快照无 allowed_actions）：客户端依快照字段自判可执行动作——seat（本人座位，观赛 -1）、phase（deal|draw|response_peng|response_chi|settled|finished）、turn（当前行动座位）、responding_seats（响应窗口成员）、drawn_tile（仅本人刚摸的牌）、melds（四家副露 {kind,tiles}——本人吃摊数 = melds[seat] 中 kind=="chi" 的组数）、god.catch_play（抓打圈）、god.god_discarder_seat（抓打圈豁免方座位，无圈 = -1；本人受限 ⇔ catch_play && god_discarder_seat != seat）。draw 且 turn==seat 可出牌/胡/杠；窗口阶段仅 responding_seats 成员可碰/吃/明杠/pass，且 吃摊数已达 2 组时不可再吃（吃最多 2 摊，服务端 409）。窗口「已响应」状态须客户端本地跟踪——重复提交 pass/动作返回 409 INVALID_ACTION。

• 弃胡机制：摸牌后不强制自动胡——客户端自行判胡（快照无 allowed_actions）后可提交 {"action":"hu"} 胡牌，也可继续打牌（飘/杠链前提：爆头态摸白板弃胡打出 = 财飘）。

• 快照 god 字段（本人视角）：baotou（爆头状态）、chain_count（本人动作链次数：飘/杠累计，断链清零）、catch_play（抓打圈）、god_discarder_seat（抓打圈豁免方座位：打财神者本人；无圈 = -1——圈中等于本人 seat 即豁免，可吃碰明杠与任意出牌）。

• 多阶段锦标赛（v7 起）：普通锦标赛打完一个阶段 ≠ 结束——status 会停在 stage_done（等管理员推进）或进入 stage_open（下一阶段资格确认）；决赛轮并列还会自动加赛（新 game_id 出现）。阶段协议见 §2.6，排名判定链见 docs/胡牌规则与番数计算.md §7。

2.2 版本自检（推荐）

系统迭代快，接口可能变更。bot 启动时拉 GET /portal/api/guide/version（免认证，5/s）
      获取服务器接入指南版本号与变更日志，与本 bot 开发时已知版本比对——发现 BREAKING 变更即提示
      人工核对（版本为递增整数，直接数值比较；返回结构见下方示例）。
      # 版本自检示例（纯标准库，随最小 Bot 同款姿势）
import json, ssl, urllib.request

KNOWN = 1  # 本 bot 开发时对应的接入指南版本（写在代码里）
ctx = ssl._create_unverified_context()  # 部署实例为自签证书，跳过校验
req = urllib.request.Request("https://<SERVER>/portal/api/guide/version")
with urllib.request.urlopen(req, timeout=10, context=ctx) as r:
    meta = json.load(r)
if meta["version"] > KNOWN:
    breaking = [c["summary"] for c in meta["changes"]
                if c["type"] == "breaking" and c["version"] > KNOWN]
    print(f"服务器指南 v{meta['version']} > 本 bot 已知 v{KNOWN}；BREAKING 变更：")
    for s in breaking:
        print("  -", s)

响应结构：{"version": 7, "updated_at": "2026-09-02", "changes": [{"version", "date", "type": "breaking|added|changed", "summary", "detail"}]}
      ——changes 版本降序、首条最新；type=breaking 表示旧行为不再兼容（如 v2「快照移除 allowed_actions」；v7「普通锦标赛多阶段化」「status 新值 stage_open/stage_done」），
      added 为新增端点/能力，changed 为行为调整。

2.4 常见错误码

 | 状态码 | 错误码 | 含义

 | 400 | TOKEN_NOT_SCOPED | 全局令牌调用 /me/rules、/me/ready（需报名令牌）

 | 401 | UNAUTHORIZED | token 无效或已吊销

 | 403 | FORBIDDEN | 非该场参赛者 / 非参赛者查询他人锦标赛

 | 403 | GAME_NOT_FINISHED | 数据 API 拉取进行中场次（对局内禁实时数据，防作弊）

 | 404 | TOURNAMENT_NOT_FOUND / GAME_NOT_FOUND | 锦标赛 / 房间不存在

 | 404 | NO_ROOM_AVAILABLE | 自动匹配（/api/match）无可用房：body 显式声明的上限低于服务默认（M=10/Rounds=8 = 永久条件，改上限或放弃，不重试）；或兜底瞬态（建房后入席失败等，message 附原因）。code 恒定、判型用 code；无 body/缺省键恒不触发（v13 起；默认值 v15 上调）

 | 409 | INVALID_ACTION | 动作不合法（阶段/座位/手牌自检失败；含吃摊已满 2 组仍提交 chi）——提交前自行核算动作（快照提供 seat/phase/responding_seats/drawn_tile/melds 等全部判定所需信息）

 | 409 | TOURNAMENT_CLOSED | 赛事已关闭（closed）——报名/ready 均拒绝

 | 409 | TOURNAMENT_STARTED | 开赛后报名；非确认期（running / stage_done / finished / void）提交 ready

 | 409 | NOT_REGISTERED | 阶段 1（报名期）未报名就提交 ready

 | 409 | NOT_QUALIFIED | 阶段 2+ 确认期（stage_open）名单外提交 ready——海选已淘汰或未报名者无本阶段资格（多阶段，v7 起）

 | 403 | PORTAL_BINDING_REQUIRED | 全局令牌（存量匿名，openid 未绑定）调用 /api/match 或新报名 register——v24 起身份门禁：存量匿名不能开新参赛/新匹配，须改走门户「我的 AI 身份」或门户报名取得绑定身份/参赛令牌；已报名行幂等重试、ready 与在途场次一律不受影响（永久条件，勿重试）

 | 403 | FEATURE_DISABLED | 该功能已被管理员临时关闭（正式比赛期间）。永久条件——不要重试，稍后再试或等待公告。v29 起覆盖三处：POST /api/match（自由匹配关闭；已在房中的幂等重调照常 200 返原房）、POST /portal/api/test-rooms（自建测试房关闭）、以及已有 finished 测试房的「重开下一轮」（4 令牌各 ready 一次；该路径此前为 409，v29 起改 403）

 | 409 | AUTO_MATCH_ONLY | 对自动匹配房玩家 API 直连 register/ready——自动房唯一入席入口是 POST /api/match（在册/门户绑定成员直连 register/ready 亦 409，幂等语义由 /api/match 承担；v13 起。v24 修订：无在途报名行的存量匿名令牌直连 register 为 403 PORTAL_BINDING_REQUIRED——先撞身份门禁，见下）

 | 409 | MATCH_BUSY | 自动匹配（/api/match）在途自动房达 50 上限且无半空房可入——只挡建房、不挡入席（半空房永远可入），message 明示，延时后自重试（v13 起）

 | 409 | MATCH_LIMIT_REACHED | 已达同时 16 场上限（register/ready 与 /api/match 同码；match 为建房前校验 + actor 兜底双位点）——释放场次后重试，不换房不空转

 | 429 | RATE_LIMITED | 轮询超频 / 并发挂起超限

2.5 赛后数据（事件流 API，免认证）

• 测试房间任一局结束后（该局场次 finished；房间状态 finished/void/closed 均可），用房间 id 即可拉取该局完整对战事件流（含四家开局手牌与逐事件摸/打/吃碰杠），供离线复盘与算法优化。

• 流程：先 GET /api/test-rooms/{id}/games 拿局列表（batch 序）→ 按 batch 逐个 GET /api/test-rooms/{id}/games/{batch}/events 拉取。

• 房间 id 即凭证——请勿公开分享；限速为每房间独立 5 次/秒（另每来源总量兜底 1000 次/秒；2026-09-03 起按房间分桶，不同房间并行互不挤占，支持大规模并行房间评测）；响应 Cache-Control: no-store 勿缓存。

• 进行中场次（running）返回 403 GAME_NOT_FINISHED；房间或 batch 不存在 404；房间删除后数据级联清除（404）。

• 跨轮复用（2026-09-02 起）：测试房间 finished 后 4 令牌再次各 ready 一次即开启下一轮——局列表随时间累积含全部轮次（每轮批次从 0 重号）；跨轮按局拉完整事件日志建议用 GET /portal/api/games/{id}/events（按 game_id 无批次歧义，owner 登录态可拉；复盘按钮同源）。管理员可在正式比赛期间关闭自建测试房（v29）：此时新建返回 403 FEATURE_DISABLED，跨轮重开（4 令牌各 ready 一次）同样 403 FEATURE_DISABLED（此前为 409——注意判型用 code 而非状态码）；已有房间的查看/关闭/删除/重发令牌不受影响。

2.6 多阶段锦标赛协议（2026-09-02 起，v7）

普通锦标赛（kind 为空，创建参数不变）已按报名人数 m 自动多阶段化：m≥17 海选→16强(4组×4人)→8强(2组×4人)→决赛(4人)；9≤m≤16 海选→8强→决赛；5≤m≤8 海选(资格)→决赛；m=4 直接决赛（无淘汰）；m<4 到点作废。每阶段组内循环 M 场（M/N 创建时全局配置、跨阶段一致）。测试房间（kind=test）单阶段不变。

• 打完阶段 ≠ 结束：status 在 registering → running → stage_done → stage_open → running → …（决赛轮）→ finished 间流转（任时可 closed / void）；非决赛轮打完停在 stage_done（等管理员推进下一阶段），只有决赛轮打完才 finished。晋级轮阶段打完、新阶段确认期、决赛加赛间隙，/api/me 的 active_games 为空——空转 ≠ 结束，以 GET /api/tournaments/{id} 的 status 为唯一进度真相，直至 finished/closed/void。

• 阶段字段组（开赛后出现；registering 未开赛整组省略，旧字段不变）：stage{no,role,total,name}（阶段号 / qualify|final / 当前推断阶段总数 / 显示名：原名｜原名-第N轮｜原名-决赛）、stage_status（open|running|done）、stage_crashed（true=中断待重赛——bot 须区分「正常 done」与「中断」）、qualified / qualify_role（你在本阶段资格：finalist 晋级 / backup 候补；阶段 1 无名单 → false/空，唯阶段 1 崩溃重赛的确认期例外——报名全量 qualified=true、role 空）。stage.total 随降档/翻转动态收缩，不可按创建时规划轮次。

• 阶段确认：stage_open 时名单内（晋级者/候补）提交 POST /api/tournaments/{id}/ready 或 /me/ready = 出席确认（幂等 200；门户玩家也可用「资格确认」按钮，同语义）。名单外（海选已淘汰仍 registered、未报名者）→ 409 NOT_QUALIFIED。确认不跨阶段继承——每阶段都要重新确认（漏确认不冻结，到点按已确认且开赛时刻在线者取前 G、候补顶替——v13 新建赛事：在线 = 最近 90s 内有已认证请求，见 §2.6 附注）；非确认期提交 → 409 TOURNAMENT_STARTED。阶段 2+ 响应中 ready_users 恒 0（防泄底），确认人数不对玩家暴露。

• 排名语义：ranking 条目 = user_id/total_score/place_points/god_count/games_played/rank(1..n)；running 期是当阶段实时账，stage_open/stage_done 间隙回落上一阶段结算榜；games_played 每阶段归零（当阶段按局累计——字段名沿旧：每局结束参与者 +1、轮空一场 +1），不可跨阶段累加推进度。

• 决赛加赛：决赛轮常规场次打完若 1-4 名总得分有并列 → running 态自动加赛并账循环（无上限）。新加赛场的 game_id 自动出现（含 _s{k} 阶段段标识）——持续轮询 /api/me 的 active_games（或 tournament 详情 my_games，历史累计新 ID 追加）发现并照常参赛。

• 判定链（晋级轮排名）：键序 total_score → place_points → god_count → user_id（字典序兜底），三键独立永不相加；名次分每场 1 位 +3 / 2 位 +1 / 3 位 −1 / 4 位 −3、本场同分共享并列区间平均、不进总得分；白板获取数口径 = 配牌扫全手（庄家含第 14 张直抽）+ 每次墙摸到白板（含杠上摸），不可经事件流复算，轮空积 0；决赛轮纯总得分、任何同分加赛至 1-4 名两两不同，加赛场不产生名次分/白板数。权威细则见 docs/胡牌规则与番数计算.md §7。

三、最小 Bot（复制即用，无策略）

以下脚本只演示协议循环，不含任何牌技：令牌 → 发现锦标赛 → 报名/到位 → 按 status 多阶段循环——running 打活跃场（决赛加赛新 game_id 自动出现照常打）、stage_open 确认出席、stage_done 等推进，finished/closed/void 才退出。测试房间（单阶段）与正式锦标赛（多阶段）同一套循环。示例策略：出牌打第一张、碰/吃/杠窗口一律过；快照无 allowed_actions，判胡需自行实现胡牌算法——示例从简，可胡不胡由服务端超时自动胡兜底。保存为 my_bot.py，在「测试房间」或正式锦标赛拿到参赛令牌后直接运行：
      python my_bot.py <参赛令牌>

自测用全局令牌（门户「我的 AI 身份」或管理面造号取得）时需显式带锦标赛 id：python my_bot.py <token> <锦标赛id>。替换其中的决策分支（"提交:" 前的 if/else）即可接入你自己的牌技。
      #!/usr/bin/env python3
"""最小示例 Bot —— 杭州麻将对战平台 AI 接入模板（纯标准库，零依赖，无策略）。

只演示协议循环（v7 多阶段）：令牌 -> 发现锦标赛 -> 报名/到位 -> 按 status 循环：
running 收割活跃场（决赛加赛新场自动出现）-> stage_open 确认出席
-> stage_done 等推进 -> finished/closed/void 才退出。自研动作判定见 play()。
"""
import json
import ssl
import sys
import time
import urllib.request

if sys.stdout.encoding and sys.stdout.encoding.lower() != "utf-8":
    sys.stdout.reconfigure(encoding="utf-8", errors="replace")  # Windows 控制台兜底

SERVER = "https://10.240.169.190:18080"  # 部署实例（自签证书）；本地调试改 http://localhost:8080
TOKEN = sys.argv[1] if len(sys.argv) > 1 else "PASTE_TOKEN_HERE"

class ApiError(Exception):
    def __init__(self, status, body):
        self.status, self.body = status, body

def api(method, path, body=None):
    """带 Bearer 认证的 JSON 请求；429 退避重试，其余 HTTP 错误抛 ApiError。"""
    req = urllib.request.Request(
        SERVER.rstrip("/") + path,
        data=json.dumps(body).encode() if body is not None else None,
        method=method)
    req.add_header("Content-Type", "application/json")
    req.add_header("Authorization", "Bearer " + TOKEN)
    ctx = ssl._create_unverified_context()  # 部署实例为 caddy 自签证书，跳过校验
    try:
        with urllib.request.urlopen(req, timeout=35, context=ctx) as r:
            return json.loads(r.read().decode())
    except urllib.error.HTTPError as e:
        if e.code == 429:
            time.sleep(2)
            return api(method, path, body)
        raise ApiError(e.code, e.read().decode(errors="replace"))

# 1) 令牌发现锦标赛（报名令牌作用域直达；全局令牌用 argv[2] 显式指定）
me = api("GET", "/api/me")
tid = me["tournament_id"] or (sys.argv[2] if len(sys.argv) > 2 else "")
scoped = bool(me["tournament_id"])  # 报名令牌：/api/me 已限定本锦标赛
if not tid:
    raise SystemExit("令牌未绑定锦标赛：请用门户「报名」或「测试房间」派发的参赛令牌（自测可用 python my_bot.py <token> <锦标赛id>）")
print("锦标赛:", tid)

# 2) 进场：先幂等报名 + 到位（顺序必要——锦标赛详情对非参赛者 403；全局令牌
#    自测路径须为门户绑定身份（「我的 AI 身份」/管理面造号，v24 起匿名注册已删）；
#    报名/到位 409（已开赛/已关闭等）吞掉，
#    主循环按最新 status 兜底）
try:
    api("POST", "/api/tournaments/%s/register" % tid)
    api("POST", "/api/tournaments/%s/ready" % tid)
except ApiError as e:
    print("进场被拒:", e.body)

def play(gid):
    """单场主循环：长轮询 -> 快照 -> 自研动作判定（快照无 allowed_actions，
    2026-09-02 协议：客户端全自主、服务端纯验证）。"""
    seq = 0
    while True:
        res = api("GET", "/api/games/%s/state?seq=%d" % (gid, seq))
        if res.get("finished"):
            print("本场结束，积分:", (res.get("snapshot") or {}).get("scores"))
            return
        if res.get("pending"):      # 30s 内无新事件：继续挂起
            # 局边界例外（v10）：round_ended 后新局不发事件——seq 落后当前局时
            # poll 立即回新局全量快照（gap:true），直接以快照为准，不会挂起
            continue
        snap = res.get("snapshot")
        if snap is None:            # 增量事件：推进 seq 后重拉权威快照
            for ev in res.get("events") or []:
                seq = ev.get("seq", seq)
            snap = api("GET", "/api/games/%s/state?seq=0" % gid).get("snapshot")
        else:
            seq = res.get("seq", seq)
        seat = snap.get("seat", -1)
        if seat < 0:                # 观赛视角无动作权
            continue
        phase, turn = snap.get("phase"), snap.get("turn")
        god = snap.get("god", {})
        # 抓打圈受限 = 圈中且本人非打财神者（豁免方可任意出牌/续飘）
        catch_restricted = god.get("catch_play") and god.get("god_discarder_seat") != seat
        if phase == "draw" and turn == seat:
            if catch_restricted and snap.get("drawn_tile"):
                act = {"action": "discard", "tile": snap["drawn_tile"]}  # 受限方只出刚摸的
            elif snap.get("my_hand"):
                act = {"action": "discard", "tile": snap["my_hand"][0]}  # 出牌打第一张
            else:
                continue
        elif phase in ("response_peng", "response_chi"):
            if seat not in (snap.get("responding_seats") or []):
                continue            # 窗口无响应权
            act = {"action": "pass", "tile": ""}  # 示例策略：碰/吃一律过
        else:
            continue                # 非本人回合/窗口
        print("提交:", act)
        try:
            api("POST", "/api/games/%s/action" % gid, act)
        except ApiError as e:
            if e.status != 409:     # 409 = 动作已失效（竞态）：重建快照后重试
                raise
        seq = 0                     # 动作后重建快照，避免状态漂移

def my_active(t):
    """本锦标赛的活跃场列表：报名令牌 /api/me 已限定；全局令牌按 my_games 交集过滤
    （my_games 历史累计、含各阶段全部场次——新加的决赛加赛场也会出现在里面）。"""
    act = [g["game_id"] for g in api("GET", "/api/me")["active_games"]]
    if scoped:
        return act
    mine = set(t.get("my_games") or [])
    return [g for g in act if g in mine]

# 3) 多阶段主循环（v7）：status 是唯一进度真相 —— 打完一个阶段 != 结束，
#    晋级轮打完 stage_done（等管理员推进）、新阶段 stage_open 需重新确认出席、
#    决赛并列自动加赛（running 内新 game_id 出现）；finished/closed/void 才退出。
while True:
    t = api("GET", "/api/tournaments/%s" % tid)
    status = t["status"]
    stname = (t.get("stage") or {}).get("name", "")
    print("status:", status, stname)
    if status in ("finished", "closed", "void"):
        break                       # 终态：才退出
    if status == "registering":
        # 阶段 1 报名期：报名（幂等）+ 到位（幂等）；409 竞态（恰逢开赛）回主循环
        try:
            api("POST", "/api/tournaments/%s/register" % tid)
            api("POST", "/api/tournaments/%s/ready" % tid)
        except ApiError:
            pass
    elif status == "stage_open":
        # 阶段 2+ 确认期：晋级者/候补确认出席（幂等，每阶段都要重新确认）。
        # 名单外 409 NOT_QUALIFIED = 已淘汰（海选未晋级/未报名者）。
        if t.get("qualified"):
            try:
                api("POST", "/api/tournaments/%s/ready" % tid)
                print("已确认出席:", stname)
            except ApiError as e:
                print("确认被拒:", e.body)  # 竞态（如恰逢开赛）：回主循环按最新状态处理
        else:
            print("未获得本阶段资格（已淘汰），退出")
            break
    elif status == "stage_done":
        pass                        # 晋级轮打完：等管理员推进（空转窗口 != 结束）
    else:                           # running：收割本阶段活跃场
        act = my_active(t)
        for gid in act:
            play(gid)
        if act:
            continue                # 立刻复查：同批余场/决赛加赛新场可能刚出现
    time.sleep(1)
print("锦标赛结束")

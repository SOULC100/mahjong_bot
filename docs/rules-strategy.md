## 1. 规则里真正影响决策的条款

| # | 规则（v30 原文要点） | 对策略的含义 |
|---|---------------------|-------------|
| R1 | **只能自摸，不允许点炮，禁止抢杠胡** | 没有点炮防守；"打安全牌"对阻止对手胡牌**无效**——对手只能靠自己摸。唯一消极防守是「别喂对手吃碰加速」 |
| R2 | 计分：庄家 ×8 / 闲家 ×1，三家分别结算 | 庄家敏感度是闲家的 2.4 倍（见 §2）；庄家身份 = 高方差 + 高惩罚 |
| R3 | 连庄：**直上三连庄**（首局即 ×8），流局庄家连庄 | 没有 ×2/×4 递增可利用；**流局会把 ×8 的庄家身份留在自己身上**（对庄家是双重伤害）。胡完续坐庄 |
| R4 | 牌墙：最后 10 墩（20 张）不摸；**最后 10 墩内禁杠**；摸完流局 | 有效可摸 63 张/局（每人约 15.8 次）；**杠有截止时间**，越早杠越自由 |
| R5 | 吃最多 2 摊（服务端 409 强制）；**碰、杠不限次数**；碰窗口先于吃窗口；吃只吃上家 | 第 3 次吃不可能：规划时就要按"最多 2 吃"配牌。碰比吃更自由（任意来源、不限次数） |
| R6 | 财神（白板）不能被吃/碰/杠/胡，可主动打出；打出财神那一圈 = **抓打圈**：其余玩家不能吃/碰/明杠、只能打刚摸的牌；**打财神者本人豁免**（可吃碰明杠、可任意出牌）；圈内吃碰后再打财神 = 链 +1 且圈以本人重启，打别的牌 = 链断且圈解除 | **打财神不是纯让牌，而是"进攻 + 全场封锁一圈"**：对手这一圈无法吃碰明杠，而自己不受限 |
| R7 | 七对：7 个对子，**禁止吃碰明杠暗杠**；财神可补对；可财飘 | 七对/七客路线与任何副露**互斥**——吃碰一次就永久放弃这条路线（爆头路线本身支持副露，不受此限） |
| R8 | 爆头：**听牌态摸任意 1 张即胡**（财神数不限，支持副露；**正好 4 张白板也算**） | 爆头是"必胡"终局形；4 白板可与爆头叠加（v21②） |

| R10 | 总番 = 1 × 分支因子 × 2^动作链次数 ×（4白板×2）×（爆头×2）；分支：平胡 ×1 / 七对 ×2 / 豪华 ×4 / 双豪华 ×8 / 三豪华 ×16 | 番型是**乘法**结构：每多一个飘/杠就 ×2，且分支/4白/爆头再连乘 |

## 2. 收益模型（决定"该优化什么"）

### 2.1 单局支付（底分 1，番型 f；座 0 = 庄）

```
庄家胡 f=1: [24, -8, -8, -8]        闲家胡 f=1: [-8, 10, -1, -1]
庄家胡 f=4: [96, -32,-32,-32]       闲家胡 f=4: [-32, 40, -4, -4]
```
真机 20 局实测逐局得分正是 `[-8, 10, -1, -1]`（f=1 闲家胡）——**模型与线上一致**。

### 2.2 各座位 EV（胜率 p，番型 f）

```
庄家: EV = 24f·p − 8f·(1−p)      = f·(32p − 8)          dEV/dp = 32f
闲家: EV = 10f·p − (10f/3)·(1−p) = f·(13.33p − 3.33)    dEV/dp = 13.33f
```

| p | 庄家 EV (f=1) | 闲家 EV (f=1) | dEV/df（闲家） |
|---|---|---|---|
| 0.25 | 0.000 | 0.000 | **0.000** |
| 0.28 | +0.960 | +0.400 | 0.400 |
| 0.30 | +1.600 | +0.667 | 0.667 |
| 0.35 | +3.200 | +1.334 | 1.334 |
| 0.40 | +4.800 | +2.000 | 2.000 |

**三个关键结论**
1. **EV ∝ f × (p − 0.25)**：番型与"胜率优势"是**相乘**关系。
2. **p = 0.25（势均力敌）时，番型的边际价值恒为 0**（dEV/df = 0）——番型只会**放大已存在的优势**。
   → 推论：四同构 bot 自对弈里，番型改动的收益会被对称化抹平；番型类改动必须用"候选 vs 3 个弱基线"才测得出来。
3. **庄家胜率敏感度是闲家的 2.4 倍**；庄家还额外承担名次分 −1.5/场（见 2.4）。
   → 座位条件策略：庄家优先保**胜率/速度**，闲家才谈得上博番型。

### 2.3 "用番型换胜率"的交换率（闲家，当前场均 f₀=1.05）

| 优势 e=p−0.25 | 提到 f=1.3 可容忍的胜率损失 | f=1.5 | f=2.0 |
|---|---|---|---|
| +0.03 | 0.58pp | 0.90pp | 1.42pp |
| +0.05 | 0.96pp | 1.50pp | 2.38pp |
| +0.10 | 1.92pp | 3.00pp | 4.75pp |

→ 真机 20 局：**场均番型 1.05（18 平胡 + 1 七对）**。也就是说：番型这个"乘法杠杆"目前几乎完全没被使用，
而且用它换胜率的额度（0.6~3pp）比想象中宽。

### 2.4 名次分与 god_count（tiebreak）

```
E[place | 庄家] = 0.25·(+3) + 0.75·(−3)        = −1.50 / 场
E[place | 闲家] = 0.25·(+3) + 0.25·(−1) + 0.5·0 = +0.50 / 场   （三家合计 0，守恒 ✓）
```
god_count：E[白板获取/局] ≈ (13 + 15.8)×4/136 ≈ **0.85 张**；每多一次杠（额外摸牌）+0.03。
→ tiebreak 的第 2/3 顺位都**偏向闲家**；god_count 量级极小，唯一可控增益是"多杠"，不值得为它改策略。

### 2.5 弃胡打财飘（爆头态）的盈亏平衡

场景：已听"任意牌"（爆头）且手里有白板。
- 选 A：立刻胡 → 番型 f₀（爆头 ×2；4 白板再 ×2）
- 选 B：弃胡打白飘 → 链 +1（×2），但要活过一圈；期间对手可能先自摸
- q = "对手在你下次摸牌前没人胡"的概率；c = 对手胡时你的损失（闲家 ≈ f_opp，庄家 ≈ 8·f_opp）

```
EV(B) − EV(A) = f₀(2q − 1) − (1−q)·c        （f₀=2）

  q\c |   c=1 |   c=2 |   c=4 |   c=8
 0.95 | +1.75 | +1.70 | +1.60 | +1.40
 0.90 | +1.50 | +1.40 | +1.20 | +0.80
 0.85 | +1.25 | +1.10 | +0.80 | +0.20
 0.80 | +1.00 | +0.80 | +0.40 | −0.40
 0.70 | +0.50 | +0.20 | −0.40 | −1.60
 0.60 |  0.00 | −0.40 | −1.20 | −2.80
```
**盈亏平衡存活率 q\***：闲家 c=1 → q>0.60；闲家 c=2 → q>0.67；**庄家 c=8 → q>0.83**。

实测 hazard（20 局、774 次摸牌、19 次有人胡）：每"对手行动"被抢先 ≈ 2.5%（全圈平均）→ 3 个对手行动
≈ 7.2% → q ≈ 0.93；但财飘时机在回合**后段**（hazard 明显更高），保守取 **q ≈ 0.75~0.80**。

→ **结论：闲家（c≤2）在 q>0.67 时就应该飘——多数情况成立；庄家（c=8）处在边界，要谨慎。**
→ 每次飘都要再活一圈，所以 n 连飘的期望是 `qⁿ·2ⁿ·f₀` vs `f₀`。
→ 4 白板特例（R9）：留 3+飘 1 = 4，**4 白板加成不丢**，于是
  `4白爆头(2×2=4) → 飘1(×8) → 飘2(×16) → 飘3(×32)`（三豪华七对路线可到 ×512）——这是番型上限线。

## 3. 由规则推出的迭代方向（按优先级）

> 每条：**规则依据 / 现状（含代码位置）/ 动作 / 验证 / 预期**

### E1 弃胡 + 财飘链（当前最大未开采杠杆）
- 依据：R11（弃胡允许）+ R8/R10（爆头 ×2、链每步 ×2）+ §2.5（q≈0.75~0.8 > 阈值 0.6~0.67）
- 现状：**引擎与线上都没实现弃胡**——`sim/engine.py` 内层 `if self._can_win(...): return self._win_result(...)` 直接强制胡；
  `smart_bot.choose_action` 也是"能胡就胡"（`can_hu` 为真立即返回 hu）。且 `should_piao` 只在"4 面子+2 财神"（尚未成胡）时触发，
  规则明确点名的"**爆头态摸到白板 → 弃胡打白飘**"这条决策根本没接；线上还把敲响路线也关着（`knock=False`，见 §1.1）。
  → 真机 20 局 0 爆头 0 财飘，正是"这些路线没打开"的直接后果。
- 动作：① 引擎加"策略可拒绝胡"的钩子（`want_hu(game, seat) -> bool`）；② 线上在 `choose_action` 的 draw 分支加弃胡判定，
  条件 = `爆头 && 白板数≥2 && q 估计 > q*`（q* 按座位取 0.60/0.67/0.83），并给"连续飘"上限（qⁿ 衰减）。
- 验证：`sim_ab`（补完 E2 后）候选 vs 基线看**平均分**；真机 `live_smoke` + `verify_live` 看番型分布变化。
- 预期：这是**唯一能直接把 f 从 1.05 抬起来**的机制性改动（每次飘 ×2）。

### E2 sim 补抓打圈（否则一切白板/财飘结论不可信）
- 依据：R6（豁免方 + 圈内禁吃碰明杠 + 圈内出牌受限）
- 现状：`sim/engine.py` 里 **grep 不到 `catch_play`**：打财神后对手照常能吃碰明杠，也无人受限。
  → 模拟器**系统性高估打财神的风险**（实际打白会封锁对手一圈），也**低估**财飘价值。
- 动作：在 `_resolve_claims` / `_discard` 里实现圈状态（`god_discarder`、`catch_play`、圈内响应集合、受限方出牌约束），
  与线上 `GameState.is_catch_restricted()` 口径对齐。
- 验证：`tests/test_sim.py` 加圈规则不变量；真机 `verify_live.py` 已有"圈内零违规"检查可比对。
- 预期：让 E1、E5 的 A/B 有意义；也解释历史上 B1"财飘"为何测不出价值。

### E3 线上补明杠 / 补杠
- 依据：R4（禁杠窗口）+ R10（每动作 ×2）+ R12（杠开是 YCB 免爆头胡法）+ 杠 = 额外摸牌（god_count/胜率）
- 现状：线上只做暗杠（`smart_bot.choose_action` 注释：明杠要响应弃牌窗口、补杠要解析 `melds` 杠/碰类型，历史上触发过死循环）。
- 动作：先做**补杠**（自己回合，`melds[seat]` 里 `kind=="peng"` 且手上有第 4 张）→ 再做明杠（响应窗口，`hand[tile]>=3`）；
  两者都要读 `wall_remaining > 20` 与"圈内受限"（R6 禁明杠）。
- 验证：单测钉住"碰后补杠不破牌数守恒"；真机烟测看 `gang` 事件是否出现。
- 预期：番型 +额外摸牌；是 E1 之外的第二个"番型来源"。

### E4 路线承诺：副露 vs 七对/爆头
- 依据：R7（七对禁一切副露）+ R8（爆头支持副露）
- 现状：`decision.should_chi/should_peng` 只看"向听数是否下降"（`sim_ab` 已证明吃 +5.0pp、碰 +3.2pp 是最大杠杆），
  但**没有"这一碰会不会永久毁掉七对路线"的判定**；`fan_override` 只是弱权重。
- 动作：加路线承诺器——手牌满足 `对子≥4 或 白板≥2` 时，评估"七对/七客路线"的期望番型 vs "吃碰加速"的胜率增益，
  用 §2.3 的交换率（e 越大越敢博番型）决定是否关闭吃碰。
- 验证：`sim_ab` 候选 vs 基线（**必须用"候选 vs 3 弱基线"**，因为 §2.2 结论 2）。
- 预期：把平胡为主的番型分布向七对/爆头挪。

### E5 白板资源的攻防
- 依据：R6（打白=封锁一圈且自己豁免）+ 白板总数公开（4 张，可见的只有自己手牌 + 弃牌）
- 现状：完全没有"用打白封锁对手"的战术；`should_piao` 只用于自己的番型。
- 动作：① **封锁式打白**：当下家明显在做牌（副露多）、或自己是庄家想压速时，用多余白板打一圈；
  ② **威胁感知**：由公开弃牌数出"对手手上还有几张白板"（2+ 张 = 爆头/七对潜力），据此调整自己的速度；
  ③ **对手财飘 = 危险信号**：对手打白且手留白 = 他已爆头听任意 → 我方应立即取小胡提速（对手随时自摸结束本局）。
- 验证：`sim_ab`（依赖 E2 的圈模型）+ 真机事件流（`verify_live.py` 已能定位 `catch_play` 圈）。
- 预期：中等；主要是**避免在对手已爆头时还慢慢做番型**。

### E6 庄家条件策略（规则给出的明确不对称）
- 依据：R2 + R3 + §2.4（庄家敏感度 2.4×、名次分 −1.5/场、流局留庄）
- 现状：`dealer_aware=False`（历史 A/B 认为"统一放大番型权重" −0.7pp 所以关掉）；`dealer_speed` 只在 `aggr*` 策略里开。
- 动作：不做"放大番型权重"，改做**方向性策略**：庄家 → 抢速（吃碰阈值放宽、更早听牌、少博番）；

- 验证：`sim_ab_dealer.py`（已有 harness）逐项 A/B，指标用平均分 + 庄/闲分列。
- 预期：小到中等，但方向明确、风险低。

### E7 对手"超时自动打最右"的信息利用
- 依据：R13（出牌超时自动打出**最右一张**）
- 现状：`sim/infer.py` 只用牌墙/弃牌的均匀或经验估算，不利用对手行为模式；线上无对手建模。
- 动作：事件流里 `timeout(kind=discard)` 紧邻的 `tile_discarded` 就是对手的"最右牌"（通常是最新摸到/最无用），
  用它修正对手手牌推断（也说明对手是"无响应 bot"，可对其提速）。
- 验证：离线用已归档事件流统计超时率与"最右牌"分布（我们的归档里自家 bot 超时率为 0，需要对手超时的样本）。
- 预期：对手弱时收益明显（赛事里会有大量超时 bot）。

### E8 杠的时机与结构
- 依据：R4（最后 10 墩禁杠）+ R10（×2/动作）+ R7（暗杠会毁七对/豪华七对）

- 验证：`sim_ab`（番型口径已修正，值得重跑）。

### E9 YCB（有财必拷响）专用策略

### E10 场次/方差管理
- 依据：R16（M 场/阶段、≤16 并发、`/api/match` 可声明上限）+ R15（决赛无限加赛）
- 现状：`smart_bot --m/--r` 支持声明上限（须 ≥10/8），默认不限；`live_loop` 逐波拉起。

### E11 候选评估指标口径（避免再次误判）
- 依据：§2.2 结论 2（p=0.25 时番型无价值）+ 自对弈对称性

  番型类候选必须用"候选 vs 3 弱基线"，否则结论会被对称化抹平。
- 验证：`sim_ab.py` 输出列增加"场均番型"。

## 5. 验证纪律（照这个顺序做，避免重复踩坑）

1. **改口径**（`fan.py`/`engine.py` 判据）→ 先与 `fan-calc` 对拍（`data/_probe_fancalc.py`），把权威期望值写进 `tests/test_fan.py`。
2. **改引擎**（弃胡/圈）→ 先补 `tests/test_sim.py` 不变量（牌守恒、吃≤2、圈合规），再谈策略。
3. **改策略** → `sim_ab`（候选 vs 3 弱基线，看**平均分** + 番型分布 + 胡牌率），四同构自对弈不作为番型类改动的证据。
4. **上线前** → `live_smoke.py`（零报错 + 0% 出牌超时）→ `verify_live.py`（吃摊/圈/番型三方对拍，0 违规）。
5. **记录** → 每次 A/B 的结论写进 `docs/roadmap.md §2`，口径/引擎缺陷写进本文 §4；真机数据落 `data/_smoke_fetch_*`。

## 6. 一句话总结

规则把博弈压成了"**自摸竞速 + 番型乘法**"：没有点炮防守，胜负全看**谁先摸到**、以及**摸到时的番型**。
由于 `EV ∝ f × (p − 0.25)`，而真机场均番型只有 1.05，**当前最大空间不在"更快的向听"（已接近极限），
而在"把已经能赢的牌换成更大的番"**——具体抓手就是规则明确允许、但引擎和线上都没实现的
**弃胡打财飘**（E1），以及支撑它的**抓打圈建模**（E2）与**明杠/补杠**（E3）。
